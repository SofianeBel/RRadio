## Learned User Preferences

- Prefers technical discussions and explanations in French, with concise, practical summaries of architecture and progress.
- Verify changes against the real surface before claiming success: screenshots/captures for visual fidelity, and compiling the native release executable plus verifying live process execution for runtime behavior; web bundles or headless checks alone are not proof.
- Defect fixes must address root causes by unifying state under a single source of truth (e.g. the audio element as sole authority for what is playing; cover art derived at the data boundary from `audioUrl` instead of stored per track) rather than patching parallel mechanisms, and be proven with verbatim runtime output.
- The overlay must start muted on launch, remain completely transparent to mouse clicks (`WS_EX_TRANSPARENT`) when hidden so it never interrupts game focus or desktop clicking, only accept input when summoned via hotkeys, and never steal keyboard focus or activate when shown (`WS_EX_NOACTIVATE`/`SWP_NOACTIVATE`/`SW_SHOWNOACTIVATE`) so it never flashes or shows a classic XP caption on focus loss.
- The station selector must be a smooth horizontal sliding carousel (not a visible wrapping loop), with the active station highlighted by a beige/white border and slight scale enlargement, and no stray accent lines or side bars.
- "Mute / Unmute" and "Radio / On-Demand" labels and buttons must be prominently sized, horizontally centered, placed close to the selector, and match the active station name text color. The "Off" state is handled by Mute rather than an empty radio station slot.
- Settings and secondary dialogs must use true glassmorphism with backdrop blur and reflection of underlying windows, using a multi-stop rotating gradient (beige, purple, ocean light blue, peach) rather than a solid or generic dark overlay.
- Controller/gamepad support must never monopolize input focus or lock out keyboard and mouse navigation.
- Discord Rich Presence should use the "Listening" activity type with music notes rather than a game controller icon, displaying album art for the main track, station logos for the badge, and a real-time progress bar resetting on every track transition.
- On-Demand mute must pause playback (not just silence it): when muted, On-Demand YouTube (via `youtubePlayer.pause()`) and direct audio both pause with `isPlaying=false` and the scrubber/progress freezes, and unmuting resumes from the same position; radio stations remain volume-only on mute — verified by Playwright that scrubber time does not advance while muted and advances again after unmute.
- Prioritize self-contained, plug-and-play solutions over manual local file setup (e.g. streaming audio directly from reliable CDNs and automated OAuth PKCE loopback servers).
- Validate native packaging, window overlays, and tray lifecycle early before implementing and polishing complex downstream features.

## Learned Workspace Facts

- The project is built with Tauri v2 (`src-tauri`), Rust 2021 edition backend (`rradio_lib`), React 19 frontend (`src/App.tsx`), TypeScript, Tailwind CSS, Vite, and Bun; canonical architecture, project history, and handover details live in `takeOver/PROJECT_RECAP.md`.
- Rust backend implements a pure transparent overlay via `configure_pure_overlay_window(hwnd, enable_click_through)` in `src-tauri/src/lib.rs`: strips `WS_CAPTION`/`WS_BORDER`/`WS_THICKFRAME`, applies `WS_POPUP` without `WS_VISIBLE`, sets `WS_EX_TOOLWINDOW`|`WS_EX_TOPMOST`|`WS_EX_LAYERED`|`WS_EX_NOACTIVATE` with `WS_EX_TRANSPARENT` toggled (true when hidden for click-through, false when visible), extends frame via `DwmExtendFrameIntoClientArea` with `-1` margins and forces `SetWindowPos` with `SWP_FRAMECHANGED`|`SWP_NOACTIVATE`|`HWND_TOPMOST`; this is reapplied after every `show` and followed by `ShowWindow(..., SW_SHOWNOACTIVATE)` in `set_window_visibility`, both branches of `set_settings_window_mode`, and the `RegisterHotKey` thread handlers for `F8`/`Alt+V` (wheel) and `F10`/`Alt+S` (settings) — verified by live HWND style checks (`0x94000000` hidden 14x14 vs `0x940B0000` visible 2048x272, ex `0x080800A0` vs `0x080C0098`, `WS_CAPTION` false, `WS_POPUP` true, `WS_EX_NOACTIVATE` true, `WS_EX_TRANSPARENT` true when hidden / false when visible) that the overlay stays open after F8 and shows no XP caption on focus loss/click outside (commits `b21bec3`/`beb36fd`).
- System-wide hotkeys are managed in a dedicated Win32 `RegisterHotKey` thread (`F8`/`Alt+V` for wheel, `F9`/`Alt+M` for mute, `F10`/`Alt+S` for settings, `F7`/`Alt+O` for On-Demand) and `rdev` for push-to-show keys (`Alt+Q`/`Alt+A`).
- The application integrates into the Windows system tray with a left-click toggle and right-click context menu (`Show/Hide`, `Mute`, `Settings`, `Quit`).
- The radio audio engine emulates 8 GTA Vice City stations (`flash_fm`, `wave_103`, `v_rock`, `emotion_983`, `fever_105`, `wildstyle`, `espantoso`, `kchat`) streaming 139 live tracks from Archive.org. In `src/audio/radioPlayer.ts` the audio element is the single source of truth for what is on air: a `currentRadioTrack` field reports actual playback, tracks advance sequentially on the real `ended` event, and live-broadcast seeks apply on `loadedmetadata` (seeking right after setting `src` is silently reset to 0 by browsers); the epoch clock only seeds the initial tune-in position. Every UI surface renders that same live state: the radio wheel HUD takes a `liveTrack` prop fed from `App.tsx`'s `activeLiveTrack` (`RadioTrack` is exported from `src/audio/radioPlayer.ts`, not `types/radio`), matching what Discord RPC reads so HUD and Discord cannot diverge — display-only static track lists and dead index state (`currentTrackIndex`) are deleted rather than kept in sync. Tuning static between stations is synthesized procedurally via Web Audio API (`AudioContext` bandpass filtered white noise at 1400 Hz for 200ms) without static sample files.
- On-Demand audio supports 3-level drill-down navigation (Streaming Service -> Playlists/Mixes -> Track Queue) with smooth physical slide animations; `App.tsx` prefetches the full track list of every YouTube Music playlist right after `fetchUserPlaylists` so the queue level, scrubber, and Discord always carry real titles, covers, and durations, and exact durations come from a batched `videos.list` call in `fetchPlaylistItems` (50 video IDs per request, ISO-8601 `PT#H#M#S` parsed) rather than a placeholder.
- On-Demand YouTube resilience and mute→pause semantics: premium-only tracks (e.g. `WdkDdTYLSG8` `Nas is like`) return `youtubei/v1/player` `status: UNPLAYABLE` with `reason: This video is only available to Music Premium members` and `streamingData: false`, surfacing as IFrame `onError 150`; `src/audio/youtubePlayer.ts` now forwards `onError` via `YTPlaybackErrorCallback`/`subscribeError(errorCallbacks[])` (alongside `subscribeEnded`/`subscribeTimeUpdate`, with `volume` field) and `src/audio/radioPlayer.ts` auto-skips the queue on that error (and on `<audio>` `error` for non-YouTube On-Demand) guarded by `hasFiredEnded` to avoid double-fire — verified to advance from the premium track to the next queue item. Mute for On-Demand is pause/resume (`radioPlayer.setMute(true)` calls `youtubePlayer.pause()`/`audio.pause()` and sets `isPlaying=false`; `setMute(false)` resumes; `playTrack(youtube:...)` stays paused if `isMuted` is true), while radio-mode mute remains volume-only; commit `d079600`, release smoke-verified PID 5392 at 19:34:21 on 2026-09-02.
- Google OAuth 2.0 PKCE authentication runs via a local Rust loopback server in `src-tauri/src/oauth.rs` listening on a dynamic port to capture authorization codes for YouTube Music; access tokens are refreshed transparently — `App.tsx`'s `ensureFreshYtmConfig` detects expiry via `hasValidToken` and calls `youtubeMusicService.refreshAccessToken` (refresh token + client credentials against `oauth2.googleapis.com/token`), persisting the fresh config into settings before every playlists/playlist-items fetch — and all Google API JSON is parsed through minimal typed views in `youtubeMusic.ts` (`YtListResponse<T>`, `YtThumbnails`, `YtPlaylistItem`, `YtVideoItem`) with casts only at the boundary and never `: any` (project rule `ts-no-any`).
- Discord Rich Presence socket communication (`\\.\pipe\discord-ipc-0`) runs in an isolated background thread (`discord-rpc-worker`) over a bounded Rust `sync_channel` with an 8-second backoff recovery loop to prevent UI or hotkey freezing; it reports the track and covers derived from the radio player's audio-element source of truth.
- Cover art has two pipelines: radio tracks map `Track Title - Artist` keys in `src/data/trackCovers.json` to iTunes Search API results at 600x600 (92% of 112 entries; 429 rate limits and missing results retried via alternate query formulations; Mr. Magic DJ interludes and unmatched songs intentionally fall back to station art), while On-Demand YouTube Music covers — including the curated mixes (`YTM_CURATED_MIXES` in `src/services/youtubeMusic.ts`, playable without a Google login) — are derived at the data boundary from `audioUrl` (`youtube:<videoId>`; playlistItems thumbnails picked as `maxres → high → medium → default`, because `maxresdefault` is missing on some videos the chain must end in a guaranteed fallback) so wheel HUD, queue, and Discord share one `coverUrl`; hardcoded YouTube video IDs rot (6 of 12 curated IDs were oEmbed-404 dead and silently wouldn't play; commit `e2cac57`), so replacements must be validated (oEmbed 200 + thumbnail 200) before insertion, and Discord fallback asset keys must actually exist.
- Runtime verification uses a Playwright harness in-repo (doctor check plus four drives; HUD-track stability across 4s, cover key match, cover HTTP 200) with evidence screenshots under `artifacts/verify-rradio/`; Node scripts must run from the repo root so `node_modules` resolves; flows behind the Google login are reproduced without credentials by intercepting `**/youtube/v3/playlistItems**` and `**/youtube/v3/videos` with Playwright `context.route` fixture JSON and injecting settings into localStorage (`rradio_gta6_settings_v1`) before reload — now also covers On-Demand mute-freeze (scrubber freezes while muted, resumes on unmute) and premium error-150 auto-skip (via mocked IFrame error) with evidence `artifacts/verify-rradio/ondemand-drilldown/verify-mute.png` and `verify-premium-skip.png` (temp-script pattern `scripts/verify-mute-and-premium.tmp.mjs` / `verify-mute-and-skip.tmp.mjs`, removed after run).
- Tauri embeds frontend assets from `dist/` directly into the native Windows executable (`src-tauri/target/release/rradio.exe`) at compile time, so frontend changes require recompiling, killing stale `rradio.exe` instances before smoke tests, and verifying the live process; the repo has no remote, so commits land on local `master` as conventional commits (e.g. `fix(audio)`, `chore(verify)`).
